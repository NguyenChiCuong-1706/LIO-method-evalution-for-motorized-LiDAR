# Stage 2A pre-calibration issues

| Issue and source | Finding, impact, correction | Evidence and residual risk |
|---|---|---|
| Ceres quaternion, `include/LI_init/LI_init.cpp:328,365,428` | The scalar-first `[w,x,y,z]` Ceres 2.2 `QuaternionManifold` matches the old scalar-first parameterization and the explicit Eigen constructor in the angular-velocity residual. No equation change. | Deterministic Plus/Minus, unit norm, and residual tangent Jacobian tests pass. Other cost terms were inspected, but not all have finite-difference tests. |
| Excitation cadence, `LI_init.cpp::data_sufficiency_assess` and `laserMapping.cpp` | Upstream and port both used `(frame_num % orig_odom_freq) * cut_frame_num == 0`. `frame_num` counts processed subframes, so with 10 Hz and five cuts this checked every 0.2 s instead of the intended 1 s. Both call sites now use `frame_num % (orig_odom_freq * cut_frame_num) == 0`. | Counter test covers cuts 1, 2, 5. A change of `cut_frame_num` at runtime shifts the modulo phase; the check remains periodic in frame count, not an exact wall-clock timer. |
| Jacobian capacity, `laserMapping.cpp:75`, `LI_init.cpp::data_sufficiency_assess` | Fixed 30,000 rows permit frames through index 9999; frame index 10000 wrote beyond the matrix. At about 50 subframes/s this is about 200 s from frame zero, dependent on actual processing. Matrix now grows geometrically before writing, preserving existing rows and zero-filling new rows. | Boundary tests cover 9999 and 10000; memory still grows with the acquisition duration. Extremely long sessions can run out of RAM; no silent sample drop is introduced. |
| Livox split, `preprocess.cpp::process_cut_frame_livox` | The loop started at point 1 and a boundary `-1` could omit points and produce undersized chunks. It now includes point 0, partitions all filtered points, and limits chunks to at least two points. XYZ is untouched. | Synthetic sorted/unsorted offsets, uneven five-way split, no split, integer-second crossing, and consecutive scans pass. Frames with fewer than two valid points are explicitly rejected; physical packet timestamp semantics remain dependent on the Livox publisher. |
| IMU validity, `laserMapping.cpp::imu_cbk` | Nonfinite gyro/acceleration or invalid nanoseconds previously entered buffers and could poison optimization. Such samples are now rejected with a diagnostic. Values otherwise retain rad/s, m/s² and original timestamps. | Synthetic stationary/constant-rate and invalid sample tests pass. WT901C host UART receipt stamps may jitter; no artificial timing correction was added. |
| Frame label, `/calibrated_livox` to LI-Init | LI-Init uses compensated XYZ directly; it does not apply a TF based on `header.frame_id`. Therefore the fitted extrinsic is from fixed motor-base point coordinates to IMU coordinates, `p_I=R_IM p_M+t_IM`. | A retained `livox_frame` label is misleading for RViz/TF users. No point transformation or LM-Calibr change was made. Verify the publisher frame label before using output with a TF tree. |

Other fixed arrays in the LiDAR processing path need separate long-duration stress review; Stage 2A verified the calibration Jacobian write that had a demonstrated capacity breach. No live calibration or physical sensor test was performed.
